# 01 - 项目总览

## 1.1 项目定位

Abstergo Solution 是基于 Spring Boot 2.7 + Vue 2.6 的企业级全栈解决方案，采用"基础框架模块 + 中间件模块 + 业务功能模块 + 前端管理后台"的分层架构，通过 Dubbo 进行服务间 RPC 通信，Nacos 作为配置中心。

## 1.3 模块地图

```
abstergo_solution_p/
├── 基础层（被所有模块依赖）
│   ├── common/                  通用工具包：AssertUtil、StrUtil、CollUtil、I18n、UUID、DataHolder、Delegate
│   └── shared/
│       ├── shared-pojo/         核心实体与基础接口：IBaseEntity、@LogicDeleteEntity、枚举、PageUtil
│       └── shared-api/          服务模板体系：AbstractService、AbstractFullFeatureServiceTemplate、校验注解
├── 框架层（技术能力模块，均遵循 api/impl 或 抽象/实现 拆分）
│   ├── web/                     Web 框架：BaseController、AjaxResult、认证授权、请求追踪
│   ├── sql/                     注解驱动 SQL 框架：sql-api + sql-impl + 各方言模块(sql-mysql-impl 等)，自动装配；QueryEngine DSL、GenericMapper 通用 CRUD
│   ├── cache/                   缓存框架：cache-api + cache-impl
│   ├── async/                   异步框架：事件广播、调度、分布式锁、线程池
│   ├── logging/                 日志框架：logging-api + logging-impl
│   ├── tree-struct/             树结构：tree-api + closure-list-impl（闭包表）
│   └── open-api-starter/        Knife4j/OpenAPI 自动装配 + @AjaxResponseType
├── 中间件集成层
│   ├── redis-mod/               Redisson 集成：数据持有、分布式锁、广播、缓存
│   ├── rabbitmq-mod/            rabbitmq-impl / rabbitmq-broadcast / rabbitmq-logging
│   ├── mq-mod/                  通用 MQ v2 契约（mq-api）：记录驱动消费模型 + 内存实现
│   └── xxl-job-mod/             XXL-Job 集成：IJsonJobHandler JSON 任务
├── 业务能力层
│   ├── system/                  system-api + default-system-impl：用户/角色/公司/令牌/日志
│   ├── dic/                     dic-api + dic-service：数据字典（Dubbo 独立服务）
│   ├── dynamic-view-route/      view-route-api + view-route-default-impl：动态视图路由/表单配置
│   └── script-engine/           脚本引擎 API
├── 应用层
│   ├── app/                     主应用运行包：controller(privates/publics)、form、vo、启动类
│   └── app-ui-vue/              Vue 管理后台
├── Go 轻量提供者（独立 Go module，不纳入 Maven，见 docs/go-dubbo-provider-guide.md）
│   ├── dubbo-go-starter/        可复用装配库：配置驱动契约、POJO 注册、Nacos 元数据发布
│   └── dubbo-db-demo/           示例提供者（go-user-provider :20001，单二进制）
└── 基础设施
    └── etc/                     docker-compose、数据库初始化脚本
```

### 模块职责边界（重要）

| 规则 | 说明 |
|------|------|
| 技术模块必须 api/impl 拆分 | 参照 system、tree-struct、cache、sql 的拆分模式；api 只含接口/模型/契约，不依赖具体中间件实现（sql 进一步按数据库方言拆出多个实现模块） |
| 业务实体放 api 层 | 如 `dic-api` 含实体与 Mapper 接口，供消费方依赖；实现放 service 层 |
| common 不放业务文案 | 通用国际化资源放 app 模块 `src/main/resources/i18n/`；业务模块自带 `messages-{module}.properties` |
| 存储类保持纯存储职责 | 如 mq-v2 `IMqRecorder` 仅 record/updateFlag/errorFlag/recordConsume/get，禁止内嵌重试扫描与定时调度 |
| 分发/调度分离 | 记录层只存取；重试扫描/回灌为独立外部组件（读 FAILED 主记录与 FAIL 台账行回灌），二者解耦 |

## 1.5 配置中心与配置分层

项目使用 Nacos 作为配置中心，本地 `application.yml` 通过 `spring.config.import` 拉取远程配置：

```yaml
spring:
  config:
    import:
      - optional:nacos:RABBITMQ.yml?group=DEFAULT_GROUP&refreshEnabled=true
      - optional:nacos:CoreAppDb.yml?group=DEFAULT_GROUP&refreshEnabled=true
      - optional:nacos:REDIS.yml?group=DEFAULT_GROUP&refreshEnabled=true
      - optional:nacos:${spring.application.name}.yml?group=DEFAULT_GROUP&refreshEnabled=true
```

配置分层原则：

| 层级 | 内容 | 位置 |
|------|------|------|
| 基础设施配置 | 数据源、Redis、MQ 连接信息 | Nacos（RABBITMQ.yml / CoreAppDb.yml / REDIS.yml） |
| 应用业务配置 | `tbs.*` 模块开关与参数 | Nacos 应用同名 yml 或本地 application-tbs.yml |
| 环境差异配置 | 地址、令牌等 | 环境变量（如 `${NACOS_ADDRESS}`、`${XXL_JOB_ADMIN_ADDRESS}`） |
| 代码内默认值 | Property 类字段默认值 | `@ConfigurationProperties` Property 类 |

**规则**：`optional:` 前缀必须保留（Nacos 不可用时允许本地启动）；敏感信息禁止硬编码进仓库，走环境变量或 Nacos。

```bash
# 1. 启动基础设施
```

## 1.7 通用代码规范（跨语言层通用）

### 1.7.1 注释规范（强制）

```java
/**
 * 数据字典管理控制器
 * <p>
 * 该控制器用于管理系统数据字典，提供字典和字典项的查询、新增、启用、禁用、删除等操作
 * </p>
 *
 * @author abstergo
 * @since 1.0.0
 */

/**
 * 根据字典名称模糊查询字典列表
 *
 * @param form 查询条件，包含字典编码和字典名称
 * @return 匹配的字典模型列表
 */
```

1. 类和方法必须有块注释；方法注释含 `@param` 与 `@return`。
2. 重要代码块上方加总结性块注释。
3. **禁止行尾注释**；简单代码（getter/setter/单行赋值）不加注释。
4. 注释只解释"为什么"与"做什么"，不复述代码本身。

### 1.7.2 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| 配置属性类 | `{Module}Property` | `RabbitMqProperty`、`RedisProperty` |
| 自动配置类 | `{Module}Config` | `BasicRedisConfig`、`XxlJobConfig` |
| 启用注解 | `@EnableTbs{Feature}` | `@EnableTbsCache`、`@EnableTbsRedis`（rabbitmq-mod 保留历史名 `@EnableRabbitMq`）；部分模块（如 sql）改用 Spring Boot 自动装配，无启用注解 |
| 服务接口 | `I{Name}Service` | `IDataDicService` |
| 服务实现 | `Simple{X}ServiceImpl`（本地）/ `Default{X}`（框架默认） | `SimpleSystemUserServiceImpl` |
| 表单对象 | `{Biz}Form` / `{Biz}SearchForm` / `{Biz}SaveForm` | `DicSaveForm`、`DicSearchForm` |
| 视图对象 | `{Biz}VO` / `{Biz}Model` | `UserInfoVO`、`DicModel` |
| 实体 | `{Biz}Entity` | `SystemDataDicEntity` |
| 枚举 | `{Biz}{Concept}Enum`，实现 `BaseEnum` | `DataDicFlagEnum` |
| 控制器 | `{Scope}{Biz}Controller` | `AdminUserController`、`PublicUserController` |

### 1.7.3 依赖注入

- 统一使用 `@Resource` 字段注入（项目既有风格），Dubbo 引用用 `@DubboReference(lazy = true)`。
- 配置类中 Bean 装配用构造参数或方法参数注入。

### 1.7.4 默认能力优先（强制）

项目已提供的默认能力，**能使用就使用默认能力**，禁止重复实现：

| 端 | 必须优先使用 | 禁止 |
|----|--------------|------|
| 后端 | `AbstractCrudController`、服务模板、`AjaxResult`、`AssertUtil`、QueryEngine | 手写 `get/save/delete/query` 流程、自建响应结构、重复实现断言与通用查询 |
| 前端 | `QuickUseManagementView`、`DynamicForm`、`DynamicTable`、`request.js`、`ResponsiveMixin` | 复制查询表单 + 表格 + 分页骨架、自建 axios 实例、自判设备档位 |

默认能力不足时，优先通过配置项、props、插槽、Transformer、服务钩子或覆写后调用 `super.*` 扩展；仍不满足时须在 MR 中说明理由，不得复制默认实现另起一套。详见 [CRUD 控制器与前端默认能力开发指南](../crud-default-capabilities.md)。
