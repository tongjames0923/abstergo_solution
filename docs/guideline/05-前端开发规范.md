# 05 - 前端开发规范（app-ui-vue）

> 适用范围：前端工程 app-ui-vue 的所有新增与修改，覆盖工程结构、代码风格、API 封装、国际化、路由权限、组件开发与联调流程。

## 5.1 技术栈基线

| 项 | 版本/选型 | 说明 |
|----|-----------|------|
| Vue | 2.6.10 | **禁止**混用 Vue 3 语法（Composition API 的 `setup` 语法糖等） |
| Element UI | 2.15.14 | 唯一 UI 组件库，禁止引入其他 UI 框架 |
| Vue Router | 3.x | history 模式，静态 + 动态路由 |
| Vuex | 3.x | 全局状态（user/app/permission 等 module） |
| Axios | 经 `src/utils/request.js` 统一封装 | 禁止业务代码直接 import axios |
| 样式 | SCSS | 全局变量集中在 `src/styles/` |
| Node | 16.x | 构建环境锁定 Node 16（见 Jenkins/本地要求） |

## 5.2 工程结构与文件放置

```
app-ui-vue/
├── src/
│   ├── api/          后端接口封装，按业务域一文件：{biz}.js（如 admin_user.js）
│   ├── components/   公共组件（按组件名建目录，index.vue 入口）
│   ├── views/        页面组件，与动态路由 component 路径对应（{dir}/index.vue）
│   ├── router/       路由定义与动态路由加载逻辑
│   ├── store/        Vuex modules
│   ├── utils/        工具（request/auth/permission/route-cache 等）
│   ├── i18n/         前端国际化资源
│   ├── styles/       全局样式与 SCSS 变量
│   ├── layout/       整体布局骨架
│   ├── permission.js 路由守卫（登录态/动态路由/角色校验）
│   └── settings.js   全局常量（错误码表、token 配置）
├── mock/             Mock 服务（仅开发期）
└── .env.*            环境配置（VUE_APP_BASE_API = '/api'）
```

规则：

1. 页面放 `views/`，可复用单元放 `components/`；页面禁止被其他页面 import。
2. 新增后端业务域 → 新建 `src/api/{biz}.js`，一个业务域一个文件。
3. 工具函数放 `utils/`，禁止在页面内写可复用逻辑。

## 5.3 代码风格（ESLint 强制，提交前必须通过）

工程启用 `plugin:vue/recommended` + `eslint:recommended`，关键规则：

| 规则 | 要求 |
|------|------|
| `semi: never` | **不写分号** |
| `quotes: single` | 单引号（模板字符串除外） |
| `indent: 2` | 2 空格缩进 |
| `prefer-const` | 不重新赋值的变量用 `const` |
| `eqeqeq` | 一律 `===`（null 比较除外） |
| `comma-dangle: never` | 禁止尾逗号 |
| `space-before-function-paren: never` | `function foo()` 无空格 |
| `vue/name-property-casing` | 组件 `name` 用 PascalCase |
| `vue/max-attributes-per-line` | 单行模板属性最多 10 个，多行时每行 1 个 |
| `no-debugger` | 生产构建禁止 debugger |

命令：

```bash
npm run lint          # 检查并自动修复
npm run dev           # 本地开发（代理 /api → 后端）
npm run build:prod    # 生产构建 → dist/
```

## 5.4 API 封装规范（强制）

### 5.4.1 统一经 request.js

所有 HTTP 请求必须使用 `src/utils/request.js` 导出的 `request` 函数，原因：

- 统一注入 `Authorization` 头（`settings.tokenHeader`）与 `Accept-Language`。
- 统一错误码处理：`successCode=200` 正常返回；`refreshTokenCode=[468]` 触发 **token 刷新队列**（并发请求挂起等待刷新完成后重放）；`noLoginCode=[405]` 弹窗确认后清 token 重新登录；`debugCodes=[601]` 输出 console；`noticeCodes=[701]` 走 Notification。
- 支持响应 `redirect` 字段自动跳转。

**禁止**绕过 request.js 自建 axios 实例，否则 token 刷新与会话失效逻辑全部失效。

### 5.4.2 封装模板（参照 admin_user.js）

```javascript
import request from '@/utils/request'

/**
 * 管理员查询用户
 * @param {Object} data - 查询条件
 * @param {string} [data.userNameEquals] - 根据用户名精确查询
 * @param {number} [pageNum] - 页码
 * @param {number} [pageSize] - 每页数量
 * @returns {Promise} 查询结果
 */
export function adminQueryUser(data, pageNum, pageSize) {
  return request({
    url: '/private/admin/user/query',
    params: { pageNum, pageSize },
    method: 'post',
    data
  })
}
```

规则：

1. 每个接口函数必须有 **JSDoc 注释**：功能说明、每个参数（含可选标记 `[ ]`）、返回值。
2. URL 与后端 `@RequestMapping` 完全一致（`/private/**`、`/public/**` 前缀），分页参数固定 `pageNum`/`pageSize` 走 query（`params`），请求体走 `data`。
3. 路径变量用模板字符串：`` `/private/admin/user/delete/${userId}` ``。
4. 函数命名与后端操作对应：查询 `query/get`、保存 `save`、删除 `delete`、状态切换用动词（`activateUser`/`disableUser`）。

### 5.4.3 错误码表同步（强制）

新增/修改错误码必须同步三处：后端 AjaxResult、前端 `settings.js`、[04 分册 4.3 错误码表](04-接口设计与上线规范.md#43-统一响应与错误码强制)。

## 5.5 国际化（强制）

1. 所有用户可见文案（菜单标题、按钮、提示、表单标签、表格列名）一律 `$t('key')`，**禁止硬编码中文/英文字面量**。
2. 资源文件位于 `src/i18n/`，中英文各一份，新增文案必须两份同步。
3. 后端返回的 `message` 已 i18n 化，前端直接展示，不要再翻译或拼接。
4. 页面标题经 `meta.title`（路由 meta）+ `getPageTitle` 处理。

## 5.6 路由与权限

### 5.6.1 静态路由 + 动态路由

- **静态路由**（`constantRoutes`）：登录、404、403、首页等无需权限的页面。
- **动态路由**：登录后经 `getRoutes()` 从后端拉取（有 `routeCacheService` 缓存与网关版本号比对机制），`mapComponent` 将后端 `component` 字段映射为本地组件：
  - `component === 'Layout'` → 布局组件；
  - 其余按 `require.context('@/views', true, /\.vue$/)` 解析（如后端存 `'/dashboard/index.vue'`）。
  - 找不到组件时 fallback 到 404 页面，**后端登记的 component 路径必须与 views 目录真实路径一致**。

规则：

1. 新增页面：先在 `src/views/{dir}/index.vue` 建组件，再到后端权限/菜单管理登记菜单（type=1）并填写正确的 component 路径。
2. 不得在前端硬编码业务菜单路由；动态路由加载失败时保留静态路由兜底（现状逻辑，勿破坏）。
3. 路由守卫统一在 `permission.js`：token 校验 → 用户信息 → `updateRouter()` 动态路由 → `meta.roles` 角色校验。禁止在页面内自行实现登录态判断。
4. 退出登录必须调用 `resetDynamicRoutesLoaded()` 相关重置逻辑（现状已接入，勿绕过）。

### 5.6.2 菜单与权限登记（与后端约定）

- 后端权限点 type：1=菜单、2= 数据权限、3=API接口访问权限。
- **前端菜单过滤只认 type=1 的权限记录**；新增菜单必须登记 type=1。

## 5.7 组件与页面开发约定

1. 组件 `name` 必须声明（PascalCase），供 keep-alive 与调试。
2. 列表页标准结构：查询表单（el-form inline）+ el-table + el-pagination；操作列按钮走 `confirm` 二次确认后再调删除/禁用接口。
3. 弹窗表单：el-dialog + el-form + rules 校验；提交前 `validate()`，成功后关闭并刷新列表。
4. 成功提示统一 `this.$message.success(res.message || $t(...))`；失败直接展示后端 `res.message`。
5. 组件路径选择器类交互（动态表单/视图配置场景）统一用 `el-select` + `filterable` + `allow-create` + `require.context` 枚举可选组件，参照既有实现。
6. 样式：组件私有样式用 `<style lang="scss" scoped>`；颜色/间距优先使用 `src/styles/` 已有变量，禁止散落魔法色值。
7. 组件通信：父子 props/$emit；跨层用 Vuex；禁止事件总线滥用。
8. 删除代码中的 `console.log` 调试语句后再提交（router 等框架文件的历史调试日志除外，新代码不留）。

## 5.8 环境与配置

| 环境 | 文件 | VUE_APP_BASE_API | 说明 |
|------|------|------------------|------|
| 开发 | `.env.development` | `/api` | vue.config.js devServer 代理到后端 8080 |
| 生产 | `.env.production` | `/api` | Nginx `location /api/` 反代到后端 |
| 预发 | `.env.staging` | `/api` | 同生产流程 |

规则：

1. 后端地址不写死在前端代码里：开发走 devServer proxy（目标见 vue.config.js，参考 `settings.backend`），生产走 Nginx 反代。
2. 环境差异只允许出现在 `.env.*` 与构建配置，禁止 `if (location.hostname === ...)` 式判断。

## 5.9 前端开发标准流程（Checklist）

```
1. 拿到接口契约 → Knife4j 文档确认 URL/入参/出参/错误码
2. src/api/{biz}.js 增加封装（JSDoc 齐全）
3. src/views/{dir}/index.vue 实现页面（$t 国际化、Element UI 规范）
4. 后端登记菜单权限（type=1），component 路径与 views 目录一致
5. 本地 npm run dev 联调：成功分支 + 错误分支（401/403/500）
6. npm run lint 通过；npm run build:prod 本地构建验证
7. 对照 07 检查清单前端部分自检
```
