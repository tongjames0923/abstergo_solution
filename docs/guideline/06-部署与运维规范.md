# 06 - 部署与运维规范

> 适用范围：构建、发布、配置管理与基础设施运维。按项目现状编写（Jenkins + Nginx + Nacos + Docker Compose）。

## 6.1 基础设施（Docker Compose）

开发与测试环境的中间件统一由 `etc/docker/docker-compose.yml`（项目名 `app_system_core_env`）拉起：

| 服务 | 镜像 | 端口 | 默认账号 |
|------|------|------|----------|
| MySQL 8.4 | mysql:8.4 | 3306 | root / 123456（utf8mb4） |
| Nacos 2.5.3 | nacos-server:v2.5.3 | 8848 / 9848 | standalone 模式，存储库 nacos_config |
| Redis 6.2 | redis:6.2.19 | 6379 | 密码 123456 |
| RabbitMQ 3.10 | rabbitmq:3.10-management | 5672 / 15672 | admin / admin123 |
| XXL-Job Admin 2.5.0 | xxl-job-admin:2.5.0 | 9898→8080 | accessToken 123456789，库 xxl_job |
| Dubbo Admin 0.6.0 | dubbo-admin:0.6.0 | 9600→38080 | 注册中心指向 Nacos |

规则：

1. 新增中间件一律追加到该 compose 文件，**禁止**散落单机脚本；镜像版本锁定 tag，不用 `latest`。
2. 初始化 SQL 放 `etc/sql_file/`（已有 `app_system.sql`、`nacos_config.sql`、`xxl-job/`）；新增库表脚本必须同步提交到该目录。
3. 生产环境密码不得沿用 compose 中的默认值；生产凭据只存放在 Nacos 加密配置或运维密钥库，不进 Git。

## 6.2 配置管理（Nacos）

1. 应用配置统一托管 Nacos：`application.yml` 经 `spring.config.import` 拉取远端配置；本地文件只保留启动必需与不敏感项。
2. 配置分层原则（与 01 分册一致）：
   - 环境无关的结构配置（模块开关 `tbs.{module}.enable`、行为参数）→ 共享配置；
   - 环境相关（地址、账号、密码、线程数）→ 环境专属 dataId；
   - 新增配置项必须先在 Property 类中声明字段与默认值，再在 Nacos 录入（代码先行，配置后补）。
3. 配置发布流程：修改 → Nacos 控制台「配置对比」确认 diff → 发布 → 应用验证（支持热更的配置确认生效，不支持的重启生效）。
4. **禁止**把密钥、密码提交到 Git 仓库的任何位置（含 application-*.yml 示例之外的真实值）。

## 6.3 构建（Jenkins 流水线现状）

### 6.3.1 后端

流水线要点：

```
1. 从 Gitee 拉取源码（BRANCH_NAME 参数化，构建时指定分支）
2. mvn clean package -DskipTests
3. 归档产物：app/target/*.jar
4. 传输至部署目录 DEPLOY_DIR，重启应用
```

规则：

1. 构建产物唯一为 `app/target/*.jar`（fat jar），版本号取 pom 的 `app.gateway.version` 链路，发布记录以版本号为准。
2. 跳过测试仅适用于发布流水线；开发者本地提交前必须自测（单元/接口自测），不得以流水线跳过测试为由省略验证。
3. 分支策略：`main` 为可发布分支；功能分支经合并请求（Code Review 通过后）进入 main；禁止直接向 main push 未评审代码。
4. 构建失败必须修复后重新触发，禁止手工绕过流水线打包上线（紧急 hotfix 事后补流程）。

### 6.3.2 前端

```
1. Node 16 环境执行 npm install && npm run build:prod
2. 产物 dist/ 部署至 Nginx 静态目录
```

规则：

1. 构建前必须 `npm run lint` 通过。
2. 生产构建禁止出现 debugger、mock 数据引用、开发环境专用地址。

### 6.3.3 Go 轻量提供者（独立产物）

`dubbo-go-starter` / `dubbo-db-demo` 是独立 Go module，**不纳入 Maven 与 Jenkins fat jar 链路**：

```
1. Go 1.27 环境执行 go -C dubbo-go-starter test ./...（既有纯逻辑单测）
2. cd dubbo-db-demo && go build -o dubbo-db-demo.exe .
3. 分发产物：单二进制 + 同目录 service.json
```

规则：

1. 编译前 `go build ./...` 与既有 `go test ./...` 需通过（总纲「AI 辅助开发使用说明」5 的编译边界）。
2. `service.json` 与二进制同目录分发（`Run` 传空路径时按工作目录取），环境相关值用 `NACOS_ADDRESS` / `DUBBO_PORT` 注入，禁止把真实凭据写进配置提交 Git（6.2 规则同样适用）。
3. 不产出 Dockerfile / compose 服务定义 / k8s 清单 / 部署脚本；`etc/docker/docker-compose.yml` 中的 Nacos 与 Dubbo Admin 为共享基础设施，不为 Go 服务新增容器定义。
4. 详见 [Go 轻量提供者指南](../go-dubbo-provider-guide.md)。

## 6.4 部署（后端 + 前端）

### 6.4.1 后端

1. jar 部署到 `DEPLOY_DIR`，以 systemd/nohup 方式运行（现状），启动参数中的 profile 与环境对应。
2. 应用注册中心为 Nacos（Dubbo 服务 + 配置），部署后确认：
   - 服务在 Dubbo Admin（9600）可见；
   - 日志无启动 ERROR；
   - `/public/gateway/version` 返回预期版本号。
3. 多实例部署时确认 XXL-Job 执行器与 MQ 消费者的幂等前提（见 02 分册）。

### 6.4.2 前端（Nginx，参照 nginx.conf / DEPLOYMENT.md）

要点：

```nginx
location / {
    root   {dist目录};
    index  index.html;
    try_files $uri $uri/ /index.html;   # history 模式必需
}

location /api/ {
    rewrite ^/api/(.*) /$1 break;
    proxy_pass http://{后端地址:端口};
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;              # WebSocket 支持
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

规则：

1. `try_files` 缺失会导致刷新 404，必配。
2. 静态资源开启 gzip 与 7 天缓存（现状配置），index.html 不缓存。
3. 后端地址变化时同步修改三处：nginx `proxy_pass`、`src/settings.js` 的 `backend`（开发用）、`.env.production`（如路径变化）——见 DEPLOYMENT.md。
4. 启用 HTTPS 时证书配置在 Nginx 层，应用层不感知。
5. 部署后验证：页面可访问 → 登录成功 → 动态菜单加载正常 → 一个核心业务接口 200。

### 6.4.3 Go 轻量提供者

1. 二进制与 `service.json` 同目录运行（systemd / nohup / Windows 直接运行均可）；`Ctrl+C` 退出后 Nacos 实例随心跳超时摘除（dubbo-go v3.3.2 无稳定公开停机入口）。
2. 部署后确认：Nacos 服务列表出现应用名、Dubbo Admin 服务查询可见方法签名、注册 URL 仅 `dubbo://`（不得出现 `tri://`）、日志无启动 ERROR。
3. 多实例部署时 `port` 不得冲突，可用 `DUBBO_PORT` 逐实例覆盖；app 侧泛化引用按 `interface#group` 匹配，group 变更需同步登记侧坐标。
4. 详见 [Go 轻量提供者指南](../go-dubbo-provider-guide.md)。

## 6.5 发布检查单

```
发布前：
  [ ] 代码已过 Code Review（07 分册清单）并合入 main
  [ ] SQL 变更脚本已提交 etc/sql_file/ 并在目标库执行
  [ ] Nacos 新增/变更配置已发布并对比确认
  [ ] 接口变更已与前端同步（无破坏性变更，见 04 分册 4.7）
  [ ] Go 提供者（如涉及）：service.json 与二进制版本匹配，接口/方法签名已复核，仅 dubbo 协议
发布中：
  [ ] Jenkins 构建成功，产物版本号正确
  [ ] 备份上一版本 jar / dist（可回滚）
发布后：
  [ ] 健康检查 + 冒烟（登录、核心业务）
  [ ] Go 提供者（如涉及）：Nacos 服务列表可见 + Dubbo Admin 测试调用通过
  [ ] 日志巡检 10 分钟无异常堆栈
  [ ] 生产 Knife4j 文档开关确认关闭（tbs.knife4j.enable: false）
回滚：
  [ ] 保留上一版本产物；回滚 = 换回旧 jar/dist + 配置回退（Nacos 历史版本）
```

## 6.6 运维观测

1. 日志：框架统一 logging 模块（logging-api/logging-impl），敏感数据不落日志（密码、token、身份证等）。
2. 链路：compose 预留 skywalking.yml，生产接入 SkyWalking 时按该文件配置。
3. 定时任务：XXL-Job 控制台管理调度，任务失败告警在调度中心配置；代码侧新增任务遵循 02 分册 2.4.4。
4. MQ 监控：失败消息经重试链路（见 02 分册 2.4.3），运维关注失败存储堆积量。
